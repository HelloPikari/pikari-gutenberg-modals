# Session 5 — five releases, and a security hole found while fixing something else

## Where this started

A collision check with the kindler-wordpress session over #484, then watching 2.2.0 out. From
there: Kindler's eyebrow bug (2.2.1), clearing the plugin's open todos (2.2.2), a logged-in
WPForms bug that turned into a security fix (2.2.3), and two removals (2.3.0). All five are
published and installed on both Kindler sites.

## Decisions worth keeping

**Print late inline CSS rather than re-enqueue (2.2.1).** Core appends each block style
variation rule to a stylesheet a block theme already printed in `<head>`, and never prints a
done handle again. Measured: the reprint was 0 bytes. The container render now snapshots what
done handles carry and prints only what was appended.

**Measure the cheap fix before building it (#132).** The todo said "dispatch the event".
Measured first: the event fired and the clone stayed unbound, because no listener existed on a
page whose modal was inline. The page-side initialiser is the part that actually mattered.

**Move the container render to `wp_footer` 10, not a WPForms-specific rerun (#135).** Both
probes produced identical assets and a working submit. Priority 10 fixes the whole class —
any plugin choosing footer assets from what rendered — without depending on WPForms internals.
The cost, stated in the PR: a trigger printed by a later `wp_footer` callback finds no container.

**Drop Cmd+M instead of rebinding it (#136).** Playwright's keypress bypasses the menu bar, so
the automated test passed. Steve's real keyboard minimised the window. Every nearby chord is
taken by Chrome, VoiceOver or core, so the honest fix was to stop advertising a shortcut.

**The endpoint may serve only what a logged-out visitor could see (#139).**
`is_post_publicly_viewable()` plus no password, and the same 404 as a missing post, so it is not
an existence oracle. The route stays public because the frontend needs it.

**Logged-in renders via core's REST cookie auth, not a WPForms nonce shim (#141).** Generic, and
it is what WordPress already does. The constraints are where it breaks: the nonce goes in the
page only for logged-in viewers, because page caches serve that HTML to everyone. The browser
cache, not the CDN, is the real trap, so every response varies on `X-WP-Nonce` and logged-in
responses are never stored. The visibility fix had to land first so authentication could never
widen access.

**Ship 2.2.2 before #510.** 2.2.2 had just been tested on Kindler. Folding in an auth and
caching change would have invalidated that testing for a bug that already existed.

**Remove the prefetch hints, don't gate them (2.3.0).** Unused, expensive when on — and they
never worked: their URLs lacked `modal_id`, so they warmed a cache entry nothing read.

## What surprised us

**The security hole was found by reading the endpoint to add authentication.** Before deciding
who a request runs as, I checked what it hands out anonymously. It checked `post_status` alone,
since the initial commit. Password-protected pages came back in full, and WPForms form settings
came back by ID — **including form 593 on live Kindler**, confirmed with one read-only GET and
now 404. The lesson: before changing an endpoint's auth, read what it already serves to nobody.

**"Works on Kindler" was not evidence for #509.** Kindler has a WPForms form in its footer on
every page, so WPForms always loaded its assets. A template-only modal form on a page with no
other form was unstyled and its submit was rejected, with the error hidden inside the
closed modal.

**Logged-out QA passed everything #510 broke.** The failure appeared only in a browser logged in
as admin. WPForms prints and checks its nonce only for logged-in users. QA both ways now.

**The review agent found two regressions my tests could not.** A logged-in request carrying only
`If-Modified-Since` could still 304 against an anonymous body, and a stale nonce dropped straight
to the anonymous render. Both tests passed because they checked what I had thought of.

**Local Kindler's plugin header said 2.2.0 while its PHP was 2.2.1.** The earlier patch copied
two files. wp-admin's version number was not the code.

## My own mistakes

- **A placeholder heredoc shipped.** One Bash call chained commit, push and PR creation with
  two heredocs, one never terminated. It pushed a commit whose message was "MSG_PLACEHOLDER" and
  opened #136 with an empty body, and its description said "dry check". It was squash-merged
  with a written message, so it never reached `main`. Rule: one heredoc per call, never
  chained with a push.
- **I told Steve #510 "doesn't affect Kindler today"** an hour before finding the hole that
  did. True for #510, false for #512; corrected in the next message.
- **Parallel Edits on one file happened once** (BlockSupportTest). Both landed, confirmed by
  grep, but don't.
