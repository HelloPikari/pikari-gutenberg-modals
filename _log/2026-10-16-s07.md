# Session 7 — scripts 36 and a browser-level test suite

2026-10-15 to 16. The monorepo session sent this work for Steve. First came the `@wordpress/scripts`
36 migration (PR #162). Then came the Playwright e2e and visual suite (PR #163), which found a
real accessibility gap on its first run. Both are merged. Nothing has been released yet.

## Decisions and why

- **Jest → Vitest along with scripts 36, not separately.** The monorepo template had already
  moved, and a second PR would have touched the same configs twice. The 192 JS tests passed before
  and after the swap. That check is how we know the swap changed no behaviour.
- **CI Node 20 → 24 in the same PR.** scripts 36 requires Node ≥ 24.15. The edit was blocked by
  auto mode until Steve allowed it. The bump has to be in this PR, because otherwise CI fails on
  install.
- **Kept `@wordpress/interactivity` at ^7.0.0, a major bump.** It is a webpack external and is
  mocked in tests, so the version only affects types and mocks, never the shipped bundle.
- **e2e runs against a logged-out visitor on the wp-env _tests_ instance, and it seeds itself.**
  It does not depend on `npm run seed`, and it does not share state with the dev site. The
  `afterStart` pretty-permalinks hook is load-bearing. Without it, `url_to_postid()` returns 0,
  and every trigger takes the iframe path, so the tests pass against the wrong code path.
- **Visual baselines are macOS-only, and CI doesn't run e2e.** Linux baselines would double the
  maintenance for a solo dev. The behaviour specs could move to CI later as they are (see
  roadmap).
- **The focus-trap spec asserts "never on an outside element", not "never leaves the dialog".**
  The trap is `inert` plus a `focusin` redirect, so Tab past the last element reaches browser
  UI, the same as a native `<dialog>`. Asserting the stricter version would have meant
  rewriting a trap that already behaves correctly.
- **The `aria-expanded` fix was done test-first and folded into #163.** The new suite exposed
  the gap. Steve asked for the fix, and splitting it into another PR would have left a suite
  whose tests fail.

## What surprised us

- **Only the Button trigger ever announced `aria-expanded`.** Inline-format links and Group
  link-cards were missing both the attribute and its `state.isExpanded` binding. The 8-site
  `TriggerMarkup` extraction in Session 6 preserved byte-identical output, and that included
  preserving this gap. Byte-identity proves a refactor changed nothing, not that the output was
  correct.
- **jsdom runs inline scripts in their own window.** Two tests asserted on globals that an
  inline script set, and they broke under Vitest. They now assert on `document.body.dataset`,
  which the inline script and the test both see.
- **Mutation checks matter for e2e too.** The inert spec didn't fail when `inert` was removed
  until it got its own test. Each of the five deliberate breakages now turns a test red.
