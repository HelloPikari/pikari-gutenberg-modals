# Session 6 — tech debt into 2.3.1, and a cache that wasn't ready

2026-09-16. Started as "what's outstanding now that Kindler is done". The answer turned into a
cleanup release: 2.3.1 shipped with two refactors, and the third item was built, reviewed and
held back.

## Decisions and why

- **Guardian Capital is out of scope.** Steve has no control over the site. #461 now covers CCLF only.
- **`core/cover` stays out of the trigger blocks (#473, pass).** Its root holds background
  spans and an inner container, so it would need its own render path. It would also put a second
  click surface on a full-width hero. A Group wrapper works, and the filter is the opt-in.
- **Second `BlockSupport`: static helpers, not a shared instance.** Nothing
  `get_post_content_with_styles()`, `get_supported_blocks_for_js()` or `get_trigger_blocks()`
  used was instance state. `EditorIntegration` built its own copy too; the advisor caught that I
  had only planned the REST one. `suspend_container_render()` stays, because the bootstrap
  instance still hangs off `wp_footer`.
- **Decoration extraction: pin first, then move.** The existing render tests sampled two or
  three attributes per mode. The URL-link and post-link Group modes, which are the Query Loop card
  path, had none. Every attribute of all 8 sites went into tests first, with a one-line mutation to
  prove they bite. The review then diffed old against new over 522 renders. Two shapes, not one:
  a card with a link is a labelled `role=group` that hands the keyboard to its link; a card without
  one is itself an ARIA button.
- **The render cache was held out of 2.3.1 (draft #151).** Stop condition, set before the second
  review: if it finds a second request-state leak, don't ship. It found two in core (the `Host`
  header in Log in/out links, http/https in asset URLs), plus the logged-in cookie nonce case. A
  patch release is the wrong place to finish a threat model.
- **Released anyway**, since both merged refactors stood on their own. The wrap commit is local
  and was made after publishing, so it stays out of the release.

## What surprised us

- **Kindler `/about/` was never broken.** The #485 note said the trigger rendered nothing; live
  and local both render 7 working cards. The likely cause: grepping for `handleTriggerClick` when
  group cards use `handleGroupTriggerClick`. A wrong bug report cost one Playwright run to disprove.
- **Twenty Twenty-Three is a block theme, and CCLF isn't hybrid either.** cclf25 never declares
  `block-template-parts`. The hybrid check ran on Twenty Twenty-One with a three-line mu-plugin,
  so it didn't depend on anyone's login.
- **A shared server cache is a different threat model from `public` Cache-Control.** I treated
  the ETag as "the right key" because the roadmap said so. It's right for browsers, which key on
  the full URL, one browser at a time. A transient answers everyone, so `?query-0-page=999` could
  have blanked a Query Loop for all logged-out visitors for an hour.
- **I claimed the stored render was no staler than the browser's copy. Wrong the other way.**
  A browser revalidating against a post-only ETag gets a 304 and keeps its copy until the post
  changes, not for an hour. It was corrected before anything merged.
- **The advisor said the WPForms token "rotates daily". It's accepted for five years**
  (`Token::get_valid_tokens()`); `data-token-time` only sets a minimum wait. Checked in the
  source, not taken on trust.
- **Brain Monkey: `Functions\expect()` after a `when()` in `setUp()` doesn't override it.** The
  first "no hooks registered" test passed against the buggy code. An alias that records the
  calls did the job.
- **`wp-env run cli sh -c` with nested quotes fails silently.** A probe mu-plugin never got
  written, and later a `wp post update` never ran. The second nearly read as "editing a post
  doesn't invalidate the cache". `docker cp`/`docker exec` against the container name worked.
- **Refactor PRs got autolabelled `docs`** because they touched `README.md`, so they landed under
  Documentation in the draft. Relabelled `chore`, then reran Release Drafter.
- **#147 carried `skip-changelog`**, which is why the 2.3.1 draft read `* No changes`. The monorepo
  agent corrected my claim that `docs` alone caused it.
